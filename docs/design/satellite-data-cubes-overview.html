Satellite data cubes & management-zone delineation

Give the agent multi-temporal satellite processing: build (x, y, time, band) data cubes, reduce them per-pixel into multi-seasonal patterns, fuse with terrain, and cluster into agronomic management zones — then explain why each zone exists and export a variable-rate prescription.

Status  Proposed Issue  #65 (child of #27) Read path  de-risked by live spike Scope  backend · agent · UI

The gap today

The imagery pipeline today is scene → polygon → scalar: each scene is read independently and collapsed to one number per field (mean NDVI, std …). Every pixel's individuality is discarded at the earliest possible moment.

Management zones need the opposite: keep the pixels, stack them over time, fuse with terrain, then cluster and explain. That is a data cube plus a small algebra of operations on it — a new primitive, not an extension of the per-scene path.

The one load-bearing rule

Heavy datasets — cubes, derived layers, zone maps — are content-addressed server-side artifacts with stable IDs. The agent manipulates handles, never pixels.

Each cube tool consumes artifact IDs and returns a new artifact ID + a compact summary (for the model) + a render URL (for the map). This keeps the agent thin (CONTEXT.md principle #1) and generalizes two patterns already shipped: the immutable hash-keyed raster_stat_cache and the submit→poll→result raster_jobs flow.

The one departure from raster_jobs: assets point to object storage, never inline JSONB — because the payload must never reach the database or the model.

The differentiating capabilities

flagship

“Field memory” zones

Per-pixel productivity (multi-year mean) × stability (temporal CV): consistently high / low / unstable → invest, investigate, or don't bother.

novel

Phenology-shape zones

Cluster on the shape of the season curve (emergence, peak, biomass integral, senescence) — not just average greenness.

agent edge

Explainable zones

Correlate zone membership against slope/TWI/aspect; the LLM writes the causal story. Where an agent beats a GIS tool.

alerting

Anomaly-vs-self

Flag pixels deviating from their own history this season — drainage failure, pest, a machinery skip.

closes the loop

Prescription (VRA) export

Zones → variable-rate seeding/N map, exported as GeoJSON/Shapefile/ISO-XML for the tractor. The deliverable that matters.

product feel

Cube as conversation

“Re-cluster into 3”, “drop the drought year”, “mask the headlands” — cheap iteration because artifacts are cached handles.

Sequencing — each step ships value & de-risks the next

M0 · Scene-manifest enabler

Emit per-scene IDs + band hrefs from the time-series job. Tiny change, unblocks temporal playback (#58) and feeds the cube builder.

M1 · Data cube + “field memory”

Artifact registry + object store; build_cube / temporal_features on xarray+stackstac → a stability COG. Includes canonical-grid reprojection & per-pixel SCL masking (pulled in from the spike finding).

M2 · Terrain fusion

DEM provider + slope/aspect/TWI/curvature, co-registered to the cube grid. Same align step also unblocks NBR.

M3 · Zones + explanation

delineate_management_zones (cluster + validity-index k-selection) and attribute_zones, with HITL save.

M4 · Close the loop

VRA prescription export, anomaly-vs-self, (stretch) phenology features.
